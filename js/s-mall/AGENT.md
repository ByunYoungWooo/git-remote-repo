# AGENTS.md — 여성복 쇼핑몰 개발 규칙

## 1. 프로젝트 원칙
- 여성복 온라인 쇼핑몰을 개발한다.
- 기존 기술 스택과 디렉터리 구조를 우선 유지한다.
- 실제 코드와 DB를 확인한 후 작업한다.
- 존재 여부를 확인하지 않은 파일, 테이블, API를 가정하지 않는다.

## 2. 컨텍스트 관리
- 작업 시작 시 PROJECT.md, TODO.md, HANDOFF.md를 확인한다.
- 서버 기동·정지·점검은 `docs/ops.md` 절차를 따른다.
- 현재 작업과 관련된 소스 코드 및 문서만 추가로 읽는다.
- 대형 파일이나 전체 프로젝트를 무조건 읽지 않는다.
- 이미 확인한 사실을 반복 조사하지 않는다.
- 작업 범위를 벗어난 리팩터링은 하지 않는다.

## 3. 작업 진행 방식
1. 현재 구현과 관련 코드를 확인한다.
2. 변경할 파일과 구현 계획을 간단히 제시한다.
3. 계획된 범위만 수정한다.
4. 관련 테스트 및 실제 실행 결과를 확인한다.
5. 실패하면 원인을 확인하고 최소 범위로 수정한다.
6. 작업 결과와 남은 문제를 문서에 반영한다.

## 4. 금지 사항
- 확인하지 않은 DB 스키마를 임의로 가정하지 않는다.
- 기존 기능을 확인하지 않고 중복 구현하지 않는다.
- 테스트를 실행하지 않고 완료했다고 보고하지 않는다.
- 오류를 해결하기 위해 무관한 파일을 대량 수정하지 않는다.
- 실패한 명령을 이유 없이 반복하지 않는다.
- 실제 실행 결과와 추정 결과를 구분한다.

## 5. 작업 완료 조건
- 변경 파일을 보고한다.
- 실행한 테스트와 결과를 기록한다.
- 미해결 오류와 추가 작업을 기록한다.
- PROJECT.md, TODO.md, HANDOFF.md 중 변경이 필요한 문서만 갱신한다.
- 다음 작업에 필요한 정보만 HANDOFF.md에 남긴다.
