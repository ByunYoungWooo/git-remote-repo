이번 프로젝트는 다음 순서로 진행한다.

1단계. 요구사항 정의 — 가장 먼저

먼저 "무엇을 자동화할 것인가"를 확정합니다.

예를 들어:

대상: 국립공원공단 예약시스템
대상 시설: 야영장
예약 방식: 선착순 / 추첨 구분
원하는 날짜
원하는 야영장
원하는 사이트
사이트 우선순위
여러 날짜 후보
예약 오픈 시간
예약 실패 시 재시도
예약 성공 알림
사람이 개입해야 하는 단계

여기서는 코드를 한 줄도 작성하지 않습니다.

5단계. 시스템 설계

이제 기술 스택을 확정합니다.

현재 제가 생각하는 초안은:

Python
   │
   ├── Playwright
   │
   ├── Reservation Engine
   │
   ├── SQLite
   │
   ├── Logging
   │
   └── Telegram

하지만 4단계까지 끝낸 후 최종 확정하는 게 좋습니다.

7단계. 외부 시스템 분석

여기서 처음으로 실제 사이트를 기술적으로 분석합니다.

res.knps.or.kr
        │
        ├── URL 구조
        ├── 로그인
        ├── 세션
        ├── API
        ├── HTML
        ├── JavaScript
        ├── 예약 데이터
        └── 오류 처리

Playwright를 설치하는 것도 이 단계 전후가 적절합니다.

8단계. 프로토타입

전체 예약 시스템을 한 번에 만들지 않습니다.

첫 번째 목표는 딱 이것입니다.

"특정 날짜의 특정 야영장에서 예약 가능한 사이트를 자동으로 읽어온다."

예:

2026-10-10
설악산 ○○야영장

A-01  예약불가
A-02  예약가능
A-03  예약불가
A-04  예약가능

여기까지 성공시키는 겁니다.

9단계. 예약 Engine 구현

그 다음:

예약 조건
 ↓
사이트 검색
 ↓
우선순위 판단
 ↓
예약 가능한 사이트 선택
 ↓
예약 진행

을 구현합니다.

10단계. 사람 개입 지점 구현

예를 들어:

자동
 ↓
예약 직전
 ↓
🔔 "본인인증이 필요합니다"
 ↓
사용자 인증
 ↓
자동으로 계속 진행

같은 Human-in-the-loop 구조를 만듭니다.

12단계. 테스트

최소한:

단위 테스트
통합 테스트
예약 시나리오 테스트
실패 시나리오 테스트
재시도 테스트
세션 만료 테스트

를 합니다.

실제 예약을 발생시키지 않는 테스트 환경/단계부터 검증해야 합니다.

13단계. 운영 자동화

마지막으로:

systemd
   ↓
프로그램 실행
   ↓
로그
   ↓
Telegram 알림
   ↓
장애 발생
   ↓
자동 재시작

으로 운영환경을 만듭니다.

전체 개발 순서

제가 형과 같이 만든다면 정확히 이렇게 갑니다.

① 요구사항 정의
       ↓
② 실제 예약 업무 프로세스 분석
       ↓
③ 기능/비기능 요구사항
       ↓
④ 정책·제약·위험 분석
       ↓
⑤ 시스템 아키텍처 설계
       ↓
⑥ 데이터 모델 설계
       ↓
⑦ res.knps.or.kr 기술 분석
       ↓
⑧ 기술 스택 확정
       ↓
⑨ 프로토타입
       ↓
⑩ 예약 Engine
       ↓
⑪ Human-in-the-loop
       ↓
⑫ 장애/재시도
       ↓
⑬ 테스트
       ↓
⑭ 운영환경

지금 우리가 해야 할 것은 ①번입니다.

제가 보기에는 바로 코딩 들어가기보다 먼저 **국립공원 자동예약시스템 요구사항 정의서 v0.1**을 같이 만드는 게 좋겠습니다.

그걸 만들면 이후에 제가 요구사항 → 유스케이스 → 아키텍처 → DB → 클래스/모듈 → 코드 순서로 계속 연결해서 갈 수 있습니다.
