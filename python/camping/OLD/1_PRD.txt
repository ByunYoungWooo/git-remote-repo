## 1. 개요

### 1.1 목적
국립공원공단(KNPS) 예약시스템(`reservation.knps.or.kr`)의 **야영장/캠핑장 예약**을
Python + Playwright로 **반자동/자동화**하는 도구.

사용자가 날짜·장소를 알려주면, 도구가 사이트 접속 → 검색 → 예약 접수까지 처리하고,
확정된 예약 정보를 사용자에게 전달. 사용자는 그 정보를 바탕으로 **직접 입금**한다.

### 1.2 핵심 원칙
- **부하 최소화**: KNPS 공공시스템에 요청을 적게, 느리게 (rate-limit, 인위적 지연)
- **본인 명의만**: 타인 양도 금지 조항 준수. 사용자의 정보로만 예약
- **결제는 사용자가 직접**: 결제 API 자동화 없음 (PCI 부담 회피)
- **반자동 우선**: 최종 입력·확인 단계는 사용자가 직접 가능하게 설계 (ToS 리스크 최소화)

### 1.3 성공 지표
| 지표 | 목표 |
|------|------|
| 1차 테스트(attendance) 완료 | 직원 추가 플로우 정상 동작 |
| 2차 KNPS 예약 | 예약 접수 → 정보 전달 완료 |
| KNPS 요청 부하 | 요청 간 지연 ≥ 2s, 동시 접속 1개만 |
| 실패 시 | 에러 원인 명확히 보고, 재시도 1회까지만 |

## 3. 범위

### 3.1 MVP (v1.0) 포함
- **1차 테스트**: attendance(출근부) 사이트에서 **직원 추가** 플로우 자동화
  - 로그인 → 직원관리 → 직원 추가 폼 입력 → submit → 성공 메시지 확인
- **2차 KNPS 예약**:
  - KNPS 접속 → 야영장/캠핑장 검색 → 날짜·영지 선택
  - 예약자 정보 입력 (이름/연락처/인원 — 사용자에게 수집)
  - 예약 접수 완료 → 예약번호·일시·영지·요금 정보 추출
  - Telegram으로 예약 정보 전달
  - 사용자는 그 정보로 직접 입금
- **공통**:
  - Playwright (Chromium) 기반, 헤드리스/헤드드 전환
  - 요청 간 인위적 지연 (부하 최소화)
  - 에러 시 스크린샷 + 로그 저장
  - 설정은 `config.py` (URL, 지연시간, Telegram 등)

### 3.2 MVP 제외
- 대량/동시 예약 (부하·ToS 위반)
- 자동 결제 (사용자 직접 입금)
- 다중 사이트 병렬
- 크롤링/데이터 수집 (예약 목적 외)
- 모바일 앱

## 6. 기술 스택 (확정)
| 계층 | 기술 |
|------|------|
| 언어 | **Python 3.10+** |
| 자동화 | **Playwright** (sync API, Chromium) |
| 알림 | Telegram Bot API (`config.py`의 토큰/채팅ID) |
| 설정 | `config.py` (URL, 지연, 계정, Telegram) |
| 의존성 | `playwright`, `python-telegram-bot` or `requests` (Telegram) |
| 저장 | 실행 결과 로그 + 스크린샷 (`output/` 폴더) |

> 기존 `config.py`가 Selenium 기반이라, **Playwright로 전환**. Selenium 설정 부분은 Playwright로 교체한다.
